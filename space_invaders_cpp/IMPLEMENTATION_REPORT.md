## 手順ごとの実施内容

### 手順1: logic の C++ 化

- `FleetLedger` の配列を std::array にし、`ledger_xxx(FleetLedger*, ...)`
  をメンバ関数（init / kill / column_dead / bottom_enemy）に。
  update_speed は private メンバに
- 出力ポインタ引数は参照に。#define は constexpr に。
  BARRIER_DESIGN はヘッダ内の constexpr std::array に
- テストも移植し、C版と同じ **67項目すべて合格**

### 手順2: assets の RAII 化

- コンストラクタで読み込み、デストラクタで解放。SDL の資源は
  unique_ptr ＋専用 deleter で保持
- 読み込み失敗の伝え方は、C版の戻り値に一番近い `ok()` 方式にした
  （事前に伝えた選択肢どおり）。途中まで読み込んだ資源は失敗時も
  デストラクタが全部解放するので、C版で残っていた「失敗時の後始末なし」
  も結果として解消している
- 実装上の調整: deleter に SDL 関数の関数ポインタを使うと
  unique_ptr のデフォルトコンストラクタが使えず std::array に
  入れられないため、deleter は状態を持たない小さな構造体にした

### 手順3: game の C++ 化

- Game 構造体＋自由関数を Game クラスに。game_init はコンストラクタ、
  Assets は参照で保持、状態・爆発種別は enum class に
- rand() は Game が持つ std::mt19937 に置き換え（使う箇所は C版と同じ
  2か所: 敵の発射列の選択とミステリーの得点）。種は main が
  C版の srand と同じ式（SDL_GetTicks ^ time）で作って渡す
- 実装上の調整: 自機弾（24本）と敵弾（64本）で std::array の長さが違い、
  C版の「ポインタ＋長さ」の共通化がそのままでは書けないため、
  弾の生成・更新・トーチカ判定は配列の大きさのテンプレートに分けた
  （呼び出し側で敵弾か自機弾かを振り分ける薄い関数を置いた）

### 手順4: main と Makefile、スモーク比較

- Makefile は g++ ＋ `-std=c++17`、pkg-config の使い方は C版と同じ
- ビルドは `-Wall -Wextra -Werror` で警告なし
